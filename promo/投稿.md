### 项目地址

https://github.com/goodseafly/how-to-work-better

### 类别

人工智能

### 项目标题

让 AI 照 576 条职场规定回答你，每条都给得出出处

### 项目描述

一个开源的职场决策技能包，附一本 576 条的《高性价比职场指南》。装进 Claude Code、Codex 等支持 SKILL.md 的工具后，AI 会先在你本地的 book/ 目录里把相关条目查出来，再照书里的算账方式排序回答：工资少发了怎么要、年假没休完能换多少钱、被裁了能拿多少、公司让签「自愿放弃社保」签不签、竞业协议最短补偿标准。每条都注明出自第几节第几条，查不到就说查不到，不凭记忆编数字。适合要自己算清账的打工人，也适合做劳动、社保、职场类内容的人当素材库。内容按中国大陆现行规定写，证据分 A/B/C 三级，其中 A 级 518 条全部引法律、行政法规、部委规章和官方统计原文，885 处原文链接可逐条点回去核。

### 亮点

- 576 条、32 节，每条六个固定字段：成本、说人话、收益、证据等级、来源、备注。证据分级 A 518 / B 51 / C 7；A 级引的是法律法规、部委规章与官方统计原文，885 处链接能一条条回到原文
- 和网上绝大多数职场内容反着来：不给情绪给出处。查不到中立依据的宁可写「已检索，无可用依据」，地方口径一律写「按你所在省市当年公布的口径查」，不编全国统一值
- 四种成品全部由 Markdown 源文件自动生成：静态检索页（按关键词、章节、证据等级筛，也能按「花不花钱、花多少时间、要不要毅力」三样筛）、离线单文件 HTML（微信里能直接传、双击就开）、PDF、EPUB
- 三份检查器守着产出，CI 每次都跑：体例（六字段齐全、条号连续、说人话 ≤120 字、禁止裸条号）、交叉引用（821 处引用必须指向真实存在的条目）、产出对齐（9 组，含 README 真实渲染、目录与文件名对位、EPUB 结构、离线语料）。fork 下来改坏格式，CI 当场报出来
- 构建链是 Python + pandoc + typst，纯 Markdown 源文件，fork 即可自建 —— 换一套行业规则（比如医疗、教育、外贸）就能生成自己的一本
- 没做完的部分写在明处：只写「哪些信号必须去办」，不写「你这个情况该怎么处理」；各地不同的数字不给统一值，给查询方法

### 为什么改口径（别再按「书」投）

早先那份稿子写的是「分类选书籍」—— 这条是错的，已在 2026-10-07 回该站现行列表核过：它的收录流里全是带主语言的工具类项目，当天还收了一篇 AI 技能包（类别「人工智能」）。一本职场书硬塞进「书籍」大概率被判不对口；换成 **Agent Skill + 构建链** 的说法，同一个仓库就变成了它熟悉的东西。

**内容不用改，卖点换个面**：从「这本书写了什么」换成「这个东西装上去能干什么、怎么保证不出错」。

## 三、投之前过一遍这五条

1. 项目地址能打开、公开（`goodseafly/how-to-work-better`，public）
2. 在线检索页能打开、能筛（https://goodseafly.github.io/how-to-work-better/）
3. Release 里 PDF / EPUB / 离线 HTML 三个下载链接都通
4. 仓库里 `LICENSE`（CC BY 4.0）和 `LICENSE-CODE`（MIT）都在
5. **没有商业痕迹**：仓库里不放二维码、不放微信号、不放带货链接（HelloGitHub 明确拒收商业痕迹重的项目）。赞赏入口在 README 末尾与 `ads/` 里，属于「接受打赏」不属于「商业推广」，可以留

## 四、投完之后怎么判断有没有效果

别只看 Star。按这本书自己的判据（详见《职场指南_安利推广方案》第九节），信号从弱到强是：

| 级别 | 现象 | 意味着 |
| --- | --- | --- |
| 1 | Star 台阶式上涨 | 只说明被推荐了一次 |
| 2 | 有人来问「能不能转载」 | 有人想用，但还怕担责任 → 授权说明写得太难懂 |
| 3 | 有人**不问直接**搬 | 内容真的到了受众手里 |
| 4 | 出现我们没做过的形态（清单、小程序、翻译仓） | 机制启动了 —— 这是最有价值的一级 |
| 5 | 有人主动来说「我做了 X」 | 形成正循环 |

Star 是最差指标：它是结果不是原因，且能被推荐号一次性买断，涨完不产生任何二次传播。

**这一包投出去之后，要等的不是数字，是第 2 到第 5 级里的任何一条。**
